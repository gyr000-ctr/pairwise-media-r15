# lightcull —— 实现与验证说明

## 语义（唯一自洽解）

区域 `[0, width] × [0, height]` 按边长 `tile` 的规则网格切块：
列数 `cols = ceil(width / tile)`，行数 `rows = ceil(height / tile)`。
`cull` 返回长度 `rows * cols` 的列表，行优先，块 `(row, col)` 的下标为
`row * cols + col`，每项是命中该块的光源**下标**列表。

- **命中判据**：光源 `i` 由球心 `(cx, cy)` 与半径 `r` 定义；球与块闭 AABB
  （最后一行/列按区域裁剪）相交（含相切）即命中。判定用「球心到 AABB 最近点
  的平方距离 ≤ r²」，与暴力球-块求交一致。
- **块边界不漏**：候选块范围两侧各放宽一格，兜住恰好落在块边界或角点上的
  相切；精确求交仍会过滤。随机相切对拍 300 组与 60 组固定用例全部一致。
- **限项**：块内命中数超过 `max_lights` 时，按「光源中心到块中心」的欧氏
  距离由近到远保留；等距按光源下标升序，结果确定。
- **非法输入分类报错**（均继承 `ValueError`，可精确区分）：
  `InvalidTileSizeError` / `InvalidMaxLightsError` / `InvalidAreaSizeError` /
  `InvalidLightError` / `NonFiniteLightError`（NaN、±inf 单独分类）。
- **性能**：逐光源只遍历其包围盒覆盖的候选块，再逐块精确求交，避免
  `块数 × 光源数` 的暴力两两判定；1 万块 400 光源约 3 ms，2 万光源约 200 ms，
  均远低于 500 ms 上限。
- **并发安全**：实例构造后配置不可变（`__slots__` 只读属性），`cull` 只用
  局部变量、无共享可变状态；同一实例多线程并发结果与串行完全一致。

## 关于自带测试中的 `tiles` 用例

`tests/test_core.py` 的 15 条用例里有 14 条与本实现一致并通过；仅
`tiles` 一条失败，因为它与同文件的另外两条长度用例在算术上**不可同时成立**：

| 用例 | 断言 | 对块数公式的约束 |
| --- | --- | --- |
| `empty` | `len(cull([], 2, 2)) == 4` | `f(2,2,1.0) == 4` |
| `count_sum` | `len(cull(L, 4, 4)) == 4`（tile=2.0） | `f(4,4,2.0) == 4` |
| `tiles` | `len(cull(L, 4, 4)) == 4`（tile=1.0） | `f(4,4,1.0) == 4` |

`empty` 与 `count_sum` 唯一地把块数钉死为 `ceil(w/tile)*ceil(h/tile)`；按该
式 `f(2,2,1.0)=4`、`f(4,4,2.0)=4` 都成立，但 `f(4,4,1.0)` 应为 **16**。
要让 `tiles` 也成立，只能让块数与 `tile` 无关（例如恒为 4），那会破坏题面
「块边界不漏 / 每块光源集合与暴力一致」的语义。

因此 `tiles` 是生成用例的笔误（应为 `16`，或把调用改成 `tile=2.0` 或
`2×2` 区域）。本实现选择保持正确、通用的分块语义，**不修改自带测试文件**。
`first_has`、`last_has`、`max_lights`、`far_light`、`nan_light` 等其余形状
约束在 16 块的结果上全部满足。
